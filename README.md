# WhatsApp AI support agent (n8n + free AI model)

An n8n workflow that answers customer messages for a sample online shop ("Brewline Coffee Gear"). It answers from a small knowledge base (products, shipping, returns, warranty, orders), keeps the conversation history, and hands the chat to a human when it is unsure, when the customer is upset, or when the customer asks for a person.

Everything in this repo is **sample data**. There are no real customers, orders or prices.

## How a message flows

```
Customer message (webhook)
  -> Normalize            accepts a WhatsApp Cloud API payload or a simple web-chat payload
  -> Get history          last turns for this phone number (MongoDB)
  -> Build context        finds the relevant knowledge-base entries, looks up ORD-xxxx numbers,
                          decides the route
  -> Use AI?
       yes -> Call LLM    free Groq model, JSON-only answer
           -> Parse reply validates the JSON, clamps confidence, escalates when unsure or on error
       no  -> Rule reply  explicit "human" requests and non-text messages (no model call)
  -> Respond to chat      returns reply + intent + confidence + sources to the caller
  -> Log message          MongoDB: support_messages
  -> Needs a human?       yes -> Make ticket -> Create ticket   (MongoDB: support_tickets)
```

Guardrails built in:
- The model may only use the CONTEXT it is given, and must say when it does not know.
- Low confidence (under 0.6), malformed output, a model error or a timeout all end in a human hand-over, never in a made-up answer.
- Words like "human", "manager", "lawyer", "scam" skip the model and escalate immediately.
- Non-text messages (images, voice notes) get a polite canned reply.

## Setup (about 10 minutes)

1. **Get a free model key.** Create a free account at https://console.groq.com and make an API key. No card needed.
2. **Add two credentials in n8n** (Credentials, Add credential):
   - *Header Auth* named **Groq API key**: Name `Authorization`, Value `Bearer <your key>`
   - *MongoDB* (the same one you use for the stock report; host `mongodb`)
3. **Import** `workflows/whatsapp-ai-support-agent.workflow.json` (Create workflow, then the menu, Import from file).
4. Open the **Call LLM (Groq)** node and pick the Groq credential. Open the three MongoDB nodes (**Get history**, **Log message**, **Create ticket**) and pick the MongoDB credential.
5. Click **Publish** (or use "Listen for test event" and the `/webhook-test/` address).
6. Open `chat-simulator/index.html` in your browser. Click **Settings** and set the URL to your n8n address plus `/webhook/support-agent`, for example `http://localhost:5678/webhook/support-agent`.

## Demo script (6 messages)

Send these in order in the simulator. Together they show product answers, order lookup, memory, a request the agent cannot grant, and a hand-over.

1. `Hi! Do you have the burr grinder in stock?`
2. `How much is shipping, and how long does it take?`
3. `Where is my order ORD-1002?`
4. `And when will it arrive?`
5. `Can I get a 50% discount on the kettle?`
6. `I want to speak to a human`

Click **Export** in the simulator to save `support-agent-transcript.json`.

## Using real WhatsApp

The **Customer message** webhook already understands the WhatsApp Cloud API payload format. To go live you would also:
- create a Meta developer app and a WhatsApp test number,
- point the app's webhook at your public n8n URL (needs HTTPS and the `hub.challenge` verification handshake, which this project does not include),
- enable the disabled **Send via WhatsApp Cloud API** node and add your phone number ID and token.

This path is not tested here.

## Project layout

| Path | What it is |
|---|---|
| `workflows/` | the importable n8n workflow (generated by `build.py`) |
| `nodes/` | the JavaScript of every Code node, as readable files |
| `data/knowledge_base.json` | the sample shop knowledge base, embedded into the *Build context* node |
| `chat-simulator/index.html` | a WhatsApp-style chat page that calls the webhook |
| `tests/` | `node tests/run.js` runs 20 checks of routing, retrieval, hand-over and failure handling with a stub model (no n8n needed) |
| `build.py` | regenerates the workflow after you edit `nodes/` or the knowledge base |

To change the shop's content, edit `data/knowledge_base.json`, run `python3 build.py`, and re-import the workflow.

## What was tested and what was not

Tested: all Code-node logic (21 automated checks with a stub model), the chat page against a local mock of the webhook, JSON validity and connections of the workflow.

Live run (Nov 2026, self-hosted n8n in Docker, Groq model `openai/gpt-oss-120b`, MongoDB): all six demo messages above were answered correctly through the chat simulator, including the order follow-up and both hand-overs with tickets. The WhatsApp Cloud API path was not tested live.

Note on the model: Groq retired `llama-3.3-70b-versatile` on 16 Aug 2026. The workflow uses `openai/gpt-oss-120b`; change the model name in the **Call LLM (Groq)** body if Groq changes its lineup again.

Not covered by automated tests: the n8n-specific node settings (MongoDB, HTTP Request, Respond to Webhook) and the live model. The first real run in your own n8n is the proof, and the exported transcript is the record of it.
